01

Get started

Sign in, subscribe to a product, and run your first query.

What the API provides

The Humanitarian Action GraphQL API provides read-only access to humanitarian plans, projects, emergencies, organizations, locations, sectors, requirements and reported results. Use it in websites, dashboards, data pipelines and other applications.

This developer portal provides documentation, subscriptions and an API test console. The Evaluation product gives immediate access with limited usage. For regular use above those limits, request a higher tier from the SPPB-Tools team.

1. Sign in or create an account

OCHA users

Open Sign in, select Entra ID, and use your @un.org account.

Other users

Select Sign up and register with your email address and password. Activate your account using the link in the email, then sign in.

2. Subscribe to Evaluation

  1. Once signed in, open the Products page.
  2. Select Evaluation.
  3. Enter a subscription name, such as your-name-evaluation.
  4. Select Subscribe. Your subscription is active immediately.

If no APIs or products are listed, sign in first. You need an active product subscription to call the API.

3. Run a query in the portal

  1. Open APIs and select the Humanitarian Action GraphQL API, version v1.
  2. Select Try it or Try this operation to open the test console.
  3. Select your active Evaluation subscription if prompted.
  4. Paste the query below into the query field. It needs no variables; leave Variables empty or enter {}.
  5. Send the request and review the JSON response.
GraphQL query
query Currencies {
  currencies(first: 10, orderBy: { Id: ASC }) {
    items { Id Code }
    hasNextPage
    endCursor
  }
}

The Sample Queries section contains more examples. Copy the GraphQL query and its separate JSON variables into their corresponding fields.

4. Use the API from another tool

Open Profile to find your subscription keys. Send either active key in the Ocp-Apim-Subscription-Key header.

Your portal sign-in identifies your account. Your subscription key provides access when calling this endpoint from Postman or an application. See Use the API in applications for complete request examples.

Need more usage?

Contact the SPPB-Tools team to request a higher subscription tier. Include your organization, application or project, expected calls per minute and per day, and the data you need. Use the limits shown on your product page when planning requests.

Documentation and support

Read the sections in order: GraphQL basics, Filters and pagination, API model and relationships, and Schema reference. Use Requirements and results for numeric data and Sample Queries for copyable examples.

Documentation, the exported schema and reusable queries are also available in the GitHub repository. Contact the SPPB-Tools team if you need help with access or a query.

02

GraphQL basics

Build a query step by step: select fields, add a fixed filter, then use variables and relationships.

One endpoint, a query in the request body

Send queries to https://api.humanitarianaction.info/graphql/v1. The query names the data and fields to return. The response follows that selection inside a top-level data object.

REST patternThis GraphQL API
Separate resource URLsOne GraphQL URL for the documented queries
Server-defined resource responseSelect the fields your application needs
Query-string filtersUse the schema’s filter input
Related records may need separate callsSelect a relationship within the parent object
GET/POST/PATCH/DELETE by operationSend read-only GraphQL queries as HTTP POST

The supplied schema has a Query type and no Mutation or Subscription root. An APIM product subscription means API access; it is not a GraphQL real-time subscription.

1. Choose a collection and fields

GraphQL query
query Currencies {
  currencies(first: 10, orderBy: { Id: ASC }) {
    items { Id Code }
    hasNextPage
    endCursor
  }
}
  • currencies is a root field under Query.
  • items is the array of currency records.
  • Id and Code are fields on each record.
  • first: 10 requests up to ten records. hasNextPage tells you whether more remain.
Illustrative response — values shown only to explain the structure
{
  "data": {
    "currencies": {
      "items": [
        {
          "Id": 1,
          "Code": "USD"
        }
      ],
      "hasNextPage": false,
      "endCursor": null
    }
  }
}

2. Filter using a fixed value

GraphQL query
query Plan1202 {
  plans(first: 1, filter: { Id: { eq: 1202 } }) {
    items { Id Name PlanCode StartDate EndDate }
  }
}

Id: { eq: 1202 } means “return the plan whose ID equals 1202”. IDs are unique, so first: 1 is enough for this lookup. Replace 1202 with an ID returned by a plan list query.

An empty items: [] array can be a successful response: no record matched. It is not automatically an API error.

3. Put changing values in Variables

GraphQL query
query PlanById($planId: Int!) {
  plans(first: 1, filter: { Id: { eq: $planId } }) {
    items { Id Name PlanCode StartDate EndDate }
  }
}
Variables
{
  "planId": 1202
}
  • $planId is declared in the query and used in the filter.
  • Int! requires an integer value. The exclamation mark means it cannot be omitted or null.
  • The JSON key is "planId", without $.
  • Use a JSON number such as 1202, not a quoted string such as "1202".

Changing Variables does not require editing the query. Match each variable’s type to the schema; some IDs use Short or UnsignedByte, not Int.

4. Request related data

GraphQL query
query PlanWithContext($planId: Int!) {
  plans(first: 1, filter: { Id: { eq: $planId } }) {
    items {
      Id
      Name
      emergency(first: 10, orderBy: { Id: ASC }) {
        items { Id Name EmergencyType EmergencyDate }
        hasNextPage
        endCursor
      }
      location(first: 10, filter: { AdminLevel: { eq: 0 } }, orderBy: { Id: ASC }) {
        items { Id Name ISO3 }
        hasNextPage
        endCursor
      }
    }
  }
}
Variables
{
  "planId": 1202
}

The response has a plan in data.plans.items, its emergencies in emergency.items, and country locations in location.items. The relationship already selects records linked to that plan; its filter narrows the linked records further.

A collection relationship returns a connection with items. A single-object relationship does not use items. For example, Project.plan is one Plan object, while Plan.project is a paged collection.

GraphQL query
query ProjectWithPlan($projectId: Int!) {
  projects(first: 1, filter: { Id: { eq: $projectId } }) {
    items {
      Id
      Name
      ProjectCode
      PlanId
      plan { Id Name PlanCode }
    }
  }
}
Variables
{
  "projectId": 12345
}

5. Rename response fields if useful

GraphQL query
query PlanAliases {
  plans(first: 1, filter: { Id: { eq: 1202 } }) {
    items { planId: Id planName: Name }
  }
}

planId: Id returns the schema field Id under the response name planId. Filters still use the schema’s original field names.

Keep each query focused

Field names are case-sensitive: Id differs from id, and Organization.url is lowercase. Begin with a small page and a few fields. Add relationships only when needed, and inspect errors as well as data.

03

Filters and pagination

Select matching records, order the results, and retrieve every page you need.

Direct filters

GraphQL query
query CurrencyUSD {
  currencies(first: 1, filter: { Code: { eq: "USD" } }) {
    items { Id Code }
  }
}

This checks a field on the selected object. Several fields within the same filter apply together: each must match.

GraphQL query
query ReleasedPlans {
  plans(
    first: 20
    filter: { IsReleased: { eq: true }, IsRestricted: { eq: false } }
    orderBy: { Id: ASC }
  ) {
    items { Id Name IsReleased IsRestricted }
    hasNextPage
    endCursor
  }
}
OperatorMeaningExample input
eq / neqEqual / not equalId: { eq: 1202 }
inMatch one of a list of valuesId: { in: [1202, 1263] }
gt / gteGreater than / greater than or equalId: { gte: 1200 }
lt / lteLess than / less than or equalId: { lt: 1300 }
containsText contains a valueName: { contains: "OCHA" }
startsWith / endsWithText begins / ends with a valueName: { startsWith: "OCHA" }
isNullCheck whether the field is nullParentId: { isNull: true }

Available operators depend on the field’s filter input type. For example, contains applies to String fields, not Int fields. Text matching follows the underlying service settings; do not assume case-sensitive or case-insensitive matching.

AND, OR and lists

Use or: [...] when either condition may match. Use and: [...] for an explicit group of conditions that must all match.

GraphQL query
query OrganizationsNameOrId {
  organizations(
    first: 20
    filter: { or: [ { Name: { contains: "OCHA" } }, { Id: { eq: 123 } } ] }
    orderBy: { Id: ASC }
  ) {
    items { Id Name Abbreviation }
    hasNextPage
    endCursor
  }
}

in is simpler when comparing several values against the same field:

GraphQL query
query PlansByIds {
  plans(first: 10, filter: { Id: { in: [1202, 1263] } }, orderBy: { Id: ASC }) {
    items { Id Name PlanCode }
    hasNextPage
    endCursor
  }
}

For missing values, use isNull rather than treating null as an ID or an empty string.

GraphQL query
query LocationsWithoutParent {
  locations(first: 20, filter: { ParentId: { isNull: true } }, orderBy: { Id: ASC }) {
    items { Id Name AdminLevel ParentId }
    hasNextPage
    endCursor
  }
}

Relationship filters

GraphQL query
query PlansByYear($year: Int!, $first: Int!, $after: String) {
  plans(
    first: $first
    after: $after
    filter: { period: { CalendarYear: { eq: $year } } }
    orderBy: { Id: ASC }
  ) {
    items {
      Id
      Name
      PlanCode
      period(first: 10, filter: { CalendarYear: { eq: $year } }, orderBy: { Id: ASC }) {
        items { Id CalendarYear PeriodType }
        hasNextPage
        endCursor
      }
    }
    hasNextPage
    endCursor
  }
}
Variables
{
  "year": 2026,
  "first": 20,
  "after": null
}

The outer period.CalendarYear filter selects plans that have a related period for the year. The inner filter limits the period rows returned under each selected plan. Selecting a nested field by itself does not filter the parent collection.

A relationship filter does not require that relationship to be included in the response. For example, you can filter plans through period and return only Id and Name.

Ordering and cursor pagination

GraphQL query
query PlansPage($first: Int!, $after: String) {
  plans(first: $first, after: $after, orderBy: { Id: ASC }) {
    items { Id Name PlanCode PlanType StartDate EndDate }
    hasNextPage
    endCursor
  }
}
Variables
{
  "first": 20,
  "after": null
}
Field or argumentPurpose
firstMaximum requested records for this page. Start with 20; increase only as needed.
afterCursor returned by the previous request; null for the first page.
orderBySort selected records. These examples use the unique Id field for predictable ordering.
itemsThe current page of records.
hasNextPageWhether another page remains.
endCursorOpaque token to send as after for the next page.
  1. Send the first request with after: null.
  2. Read and process data.plans.items.
  3. If hasNextPage is true, copy that connection’s endCursor into after.
  4. Repeat with the same filter and ordering until hasNextPage is false.
Variables for the next page
{
  "first": 20,
  "after": "PASTE_THE_RETURNED_END_CURSOR_HERE"
}

Do not decode, build or reuse a cursor from a different query. If the filter or sort changes, restart with after: null. Data can change while you page; the responses are not a promised frozen snapshot.

Nested collections page separately

A plan’s project, location and attachment collections can each have more rows than their first limit. The outer plan cursor does not continue those collections.

When a nested collection has more data, it is usually simpler to start from its root collection and filter by the parent ID:

GraphQL query
query ProjectsByPlan($planId: Int!, $first: Int!, $after: String) {
  projects(first: $first, after: $after, filter: { PlanId: { eq: $planId } }, orderBy: { Id: ASC }) {
    items { Id Name ProjectCode PlanId IsPublished CurrentRequestedFunds }
    hasNextPage
    endCursor
  }
}
Variables
{
  "planId": 1202,
  "first": 20,
  "after": null
}

This retrieves projects for one plan using one project cursor. It avoids having a different nested cursor for each plan in an outer page.

Avoid silent truncation

Select hasNextPage and endCursor for collections that may need more than one page. A query without first still has a service page size; it does not mean “return everything”. Each additional page is another API request and uses your product allowance.

04

API model and relationships

Choose the right starting object and follow the relationships defined in the supplied GraphQL schema.

Planning context

PlanCentral planning context
→
CoordinationEntityLocal field cluster or other structure
→
SectorGlobal reference sector

These are connected objects, not levels you must always retrieve together. A plan provides context; a coordination entity supplies the plan-level name; a sector supplies the global reference name.

Metric definitions and values

AttachmentMetric definition and owner
→
AttachmentFactPlanned value and revision
AttachmentWhat is measured
→
MeasurementReported observation
→
MeasurementFactReported value

Attachment.Name describes the metric, while AttachmentFact.ValueNum contains a planned value. Reported results use MeasurementFact.ValueNum. These rows can have different meanings, dimensions and reporting periods; they are not interchangeable.

Main objects

Plan · plans

The central humanitarian planning context. Select its periods, geography, coordination entities, projects or attachments when needed.

Period · periods

A calendar or planning period. CalendarYear is here; a plan can be linked to more than one period.

Emergency · emergencies

Emergency or crisis context, with links to plans and affected locations.

Location · locations

Country or subnational geography. AdminLevel, ParentId, CountryId and Path help describe its hierarchy.

CoordinationEntity · coordinationEntities

A plan-level coordination structure. The supplied examples identify field clusters with EntityTypeId 10.

Sector · sectors

A global sector reference. A locally named coordination entity can link to one or several global sectors.

LogframeEntity · logframeEntities

An element of a plan’s logical framework. Resolve EntityTypeId to distinguish objectives, activities and other levels.

Project · projects

A humanitarian project, with its plan and links to organizations, sectors, locations and coordination entities.

Organization · organizations

An organization reference with names, abbreviation, classifications and links to plans or projects.

Attachment · attachments

A metric definition and its owner. AttachmentType distinguishes Cost, Caseload and Indicator in the supplied documentation; facts hold its values.

AttachmentFact · attachmentFacts

A planned numeric value, revision and optional dimensions for an attachment.

Measurement · measurements

A reported observation for an attachment, with a link to its plan reporting period.

MeasurementFact · measurementFacts

A reported numeric value and optional dimensions for a measurement.

PlanReportingPeriod · planReportingPeriods

A reporting period attached to a plan; measurements link here for dates and period number.

MetricType · metricTypes

Reference data that identifies the meaning of a fact’s MetricTypeId.

RevisionState · revisionStates

Reference data that explains RevisionStateId and its display name.

Currency · currencies

Currency identifier and code reference. The schema does not define a direct Currency relationship on AttachmentFact.

Unit · units

A metric unit linked from Attachment or Measurement. Check this context before combining numeric values.

Select the right starting point

  • Start at plans for a plan and its context.
  • Start at projects for a project list and its PlanId filter.
  • Start at attachmentFacts for planned values, requirements or disaggregations.
  • Start at measurementFacts for reported values.
  • Start at locations, organizations or a reference collection when those records are the result you need.

The schema also exposes explicit link collections, such as planLocationRels and projectSectorRels. Use them if you need the link IDs themselves. Most consumers can follow the object relationships instead.

Schema reference

Read the exported schema and look up the collections, fields, input types and relationships available to consumers.

What api_schema.graphql tells you

The file api-schema/api_schema.graphql is the GraphQL API contract. It describes query fields, object fields, relationships, filter inputs, ordering inputs and data types. It contains no data rows or subscription keys.

Find it in the repository’s api-schema folder or the GitHub repository. Open it in a text editor and search for type Query, type Plan or a filter input such as PlanFilterInput. The reference below is generated from the supplied schema export. Download the schema from this repository.

This file is an exported snapshot. It does not update automatically when the API changes. If a field is rejected by the live endpoint, compare against the schema currently shown by the API console or request an updated export from the API team.

For each AttachmentId + MetricTypeId:

    current  = the state 2 row, if present

Python

Copy this code into call-api.py. It uses Python’s standard library. Set the HA_API_KEY environment variable, then run python call-api.py. Replace the example plan ID with one returned by the API.

Python example
import json
import os
from urllib.request import Request, urlopen
from urllib.error import HTTPError

url = "https://api.humanitarianaction.info/graphql/v1"
query = """
query PlanById($planId: Int!) {
  plans(first: 1, filter: { Id: { eq: $planId } }) {
    items { Id Name PlanCode StartDate EndDate }
  }
}
"""
body = json.dumps({"query": query, "variables": {"planId": 1202}}).encode("utf-8")
request = Request(url, data=body, method="POST", headers={
    "Content-Type": "application/json",
    "Ocp-Apim-Subscription-Key": os.environ["HA_API_KEY"]
})
try:
    with urlopen(request, timeout=60) as response:
        raw = response.read().decode("utf-8")
except HTTPError as error:
    details = error.read().decode("utf-8", errors="replace")
    raise RuntimeError(f"HTTP {error.code}: {details}") from error
result = json.loads(raw)
if result.get("errors"):
    raise RuntimeError(json.dumps(result["errors"], indent=2))
for plan in result["data"]["plans"]["items"]:
    print(plan["Id"], plan["Name"])

Handle HTTP and GraphQL errors

ResponseWhat to check
HTTP 200Inspect the errors array before treating the request as successful. Partial data and errors can appear together.
HTTP 400Check JSON syntax, the query’s field names and variable types. Read the body for the validation message.
HTTP 401Check that the subscription key is present, correct and active. If it is, report the response to the API team; authentication failures can have other causes.
HTTP 403Read the message: access may be denied or a product quota may be exhausted. For quota responses, follow Retry-After where supplied.
HTTP 429The short-term rate limit may be exceeded. Wait for the Retry-After interval when supplied.
HTTP 5xxA service or backend problem may have occurred. Retry transient failures with a delay, then contact the API team if it persists.

Do not retry invalid queries or authentication failures in a tight loop. For transient errors, use a bounded retry count and increasing delay. Keep partial responses only if your application has an explicit rule for doing so.

Illustrative GraphQL error — exact wording varies
{
  "errors": [
    {
      "message": "The field requested by the query is not available."
    }
  ]
}

An empty result items: [] with no errors is different from a failed request. It means no matching records were returned.

Usage and keys

The API supports application use. Choose a product whose rate and quota limits fit your workload. Each page request uses the allowance; a large nested query can still be costly even if it is one HTTP call.

Store application keys in environment variables or a secret store. Do not commit real keys to GitHub or embed a shared key in a public browser application. A server-side application can call the API and return the data its users need.

For higher limits, contact the SPPB-Tools team with your organization, application, expected request volume and extraction schedule. Include page sizes and the data you need.

Report a problem

Send the endpoint, query, variables, HTTP status, error response and time of the request, including the time zone. Include any request or correlation identifier returned in the headers. Remove subscription keys and sensitive values before sharing the details.
